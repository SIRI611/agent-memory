# Step 7 — Delta and Verdict

Timestamp: 2026-09-23 20:18 (UTC-6)

## Delta
> Unlike RootMem (Towards Root Memories), which handles semantically distant but logically critical user memories by having an LLM distil at most 10 "root memory" units and a generative GPT-4o-mini router make boolean activation decisions over those units alongside semantic top-k retrieval — explicitly "instead of scanning all raw memories" — and unlike InMind, which names exhaustive full-model scoring only to dismiss it as too costly, the proposed work scores every raw stored fact for request-necessity with a cheap calibrated probabilistic evaluator and no similarity candidate stage, yielding 94.4% (full scan) / 96.8% (write-gated two-stage) target recall@5 on InMind versus 4.8% (BM25), 9.6% (MiniLM) and 8.8% for the same evaluator placed behind Jev-Mem-style hybrid anchors.

## Verdict: **Level 3 — Medium Overlap**

Justification: No single paper combines the proposal's framing and its mechanism. The closest papers split the claim between them. *Keep It InMind* (task, necessity definition, diagnosis that the query-conditioned similarity interface is the failure) and *Towards Root Memories* (same "semantically distant yet logically critical" framing in personalized memory, with a candidate-free LLM necessity router, though over ≤10 distilled units) each match on problem framing and application domain. *PACE* and *LoCoMo-Plus* also match on framing and domain but use similarity-seeded retrieval or are benchmark-only. On mechanism, *Beyond Similarity: Task-Aligned Retrieval* (TAG) already replaces similarity top-k with per-item pairwise LLM applicability judgments, but for rule documents. *Jev-Mem* already uses the same Jev evaluator to score query relevance, but only on vector+keyword-anchored candidates, and it explicitly rejects exhaustive comparison on cost. *MemReranker* already provides a small calibrated pointwise memory scorer inside retrieve-then-rerank. So the delta is defensible: nobody has shown that exhaustive, cheap, calibrated necessity scoring over raw user facts closes the InMind gap. But the delta is at the Level 3/2 boundary. A reviewer can frame it as "InMind's dismissed brute-force baseline + TAG's per-item judgment + Jev-Mem's scorer". The paper therefore has to be explicit that the contribution is (i) the empirical demonstration that the cost objection fails with a cheap calibrated scorer, and (ii) the diagnostic that candidate generation, not reranking, causes the failure (the same evaluator gets 8.8% behind anchors vs 94.4% exhaustive).

## Reviewer-risk notes (not part of the level computation)
- **Baselines filtered adversarially by construction:** InMind removed 700 candidate pairs where "BM25 and MiniLM score every memory–query pair" gave an obvious match. So the 4.8%/9.6% figures, and partly the hybrid BM25+embedding-anchor 8.8%, are low by design. Add non-filtered retrievers (text-embedding-3-large, which InMind reports raises target recall to ~7–12%), plus IMLogic / PACE / LoCoMo-Plus as out-of-construction benchmarks.
- **Missing baselines that the prior work implies:** (a) the same exhaustive scan with a generative LLM (GPT-5-mini/4o-mini YES/NO, TAG/RootMem-style), to show that the *cheap calibrated* scorer is what matters; (b) RootMem on InMind; (c) InMind's always-in-state probe (68.8% indirect accuracy). Also report indirect answer accuracy, not only recall@5.
- **Scaling and cost:** measure cost and latency against memory size N (the InMind pool is small), with an explicit break-even against embedding retrieval. This is the direct answer to InMind's "forfeits sublinear cost" objection.
- **Over-retrieval / over-warning:** InMind's limitations note that there are no negative controls. Report false-positive rate of top-5 on queries where no fact is needed.
- **Two-stage write gate:** relate the write gate to RootMem's write-time distillation and to InMind's §5.3 write-time routing. Note that Jev-Mem deliberately avoids store/discard gates to prevent premature information loss, so measure what the gate drops.
